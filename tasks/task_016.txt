# Task ID: 16
# Title: Implement Generic Service Enrichment UI System with GraphQL Schema Directives
# Status: done
# Dependencies: None
# Priority: high
# Description: Design and implement a system that allows plugins to annotate GraphQL schema fields with UI component types, enabling automatic generation of rich displays without custom React components.
# Details:
Create a comprehensive Generic Service Enrichment UI System that extends the existing CoreAPI enrichment functionality with the following components:

1. **UI Component Annotation System**:
   - Implement GraphQL schema directives (e.g., `@uiComponent(type: BADGE)`, `@uiComponent(type: URL_LINK)`) that can be applied to fields
   - Define a set of standard component types: BADGE, URL_LINK, STATUS_INDICATOR, PROGRESS_BAR, DATE_TIME, CODE_BLOCK, IMAGE, etc.
   - Allow for component-specific configuration via directive arguments (e.g., `@uiComponent(type: BADGE, color: "red")`) 

2. **Generic UI Component Library**:
   - Develop a centralized React component library in CoreAPI with implementations for each component type
   - Ensure components handle different data types appropriately (strings, numbers, booleans, arrays)
   - Support theming and accessibility requirements
   - Include documentation on how to use each component

3. **Schema Introspection Engine**:
   - Create a system that parses GraphQL schema at runtime to extract UI annotations
   - Build a mapping layer that connects schema field annotations to appropriate UI components
   - Implement caching for performance optimization

4. **Enhanced Default Display**:
   - Develop an intelligent fallback display that uses schema type information to render appropriate UI
   - Add a toggle mechanism to switch between enhanced view and raw data view
   - Support nested objects and arrays with appropriate UI representations

5. **Backward Compatibility Layer**:
   - Ensure existing custom enrichment display components continue to work
   - Implement a priority system where custom components take precedence over auto-generated ones
   - Create migration documentation for plugin developers

The implementation should integrate with the existing enrichment system in CoreAPI, leveraging the PluginEnrichment GraphQL interface and client-side display registry. The system should be designed to be extensible, allowing for new component types to be added in the future.

- Create a component registry pattern for extensibility:

// Component validation registry pattern
const componentValidators = {
  BADGE: validateBadgeConfig,
  URL_LINK: validateUrlLinkConfig,

  const validator = componentValidators[type];
  if (!validator) throw new Error(`Unknown component type: ${type}`);
  return validator(config);
}
