# Task ID: 32
# Title: Implement ICMP Ping Plugin for Network Host Discovery
# Status: done
# Dependencies: None
# Priority: high
# Description: Develop a containerized Ping plugin that performs fast ICMP sweeps to discover hosts in a network, integrating with PenPal's existing architecture and services.
# Details:
Create a new Ping plugin that leverages ICMP protocol for efficient host discovery across network ranges. The plugin should:

1. Be containerized using Docker with a Dockerfile that includes necessary dependencies for ICMP operations
2. Subscribe to MQTT topics for new network discoveries (e.g., 'penpal/discoveries/networks')
3. Upon receiving network information, queue scans using the ScanQueue service
4. Implement fast ICMP sweep functionality that can handle various network sizes efficiently
5. Track scan jobs using the JobsTracker service, updating status as appropriate
6. Process scan results and upsert discovered hosts to CoreAPI
7. Extend the GraphQL schema to support:
   - Querying ping results by network, IP range, or specific hosts
   - Checking scan status and history
   - Retrieving latency statistics for discovered hosts
8. Implement proper error handling and logging
9. Include configuration options for scan parameters (timeout, retry count, parallel scan limit)
10. Follow PenPal's plugin architecture patterns for consistency

The plugin should be optimized for performance, especially when scanning large networks, and should handle rate limiting to prevent network flooding.

# Test Strategy:
Testing should verify both functionality and integration with PenPal's ecosystem:

1. Unit tests:
   - Test ICMP sweep functionality with mock network responses
   - Verify proper parsing and handling of ICMP responses
   - Test error handling for various failure scenarios

2. Integration tests:
   - Verify MQTT subscription and message handling
   - Test ScanQueue integration for job submission
   - Validate JobsTracker updates during scan lifecycle
   - Confirm CoreAPI upsert operations work correctly

3. End-to-end tests:
   - Deploy the plugin in a test environment with known hosts
   - Trigger a network discovery and verify hosts are correctly identified
   - Test GraphQL queries to retrieve ping results and status
   - Verify latency measurements are accurate using controlled test hosts

4. Performance tests:
   - Measure scan performance on networks of various sizes
   - Test concurrent scanning capabilities
   - Verify resource usage remains within acceptable limits

5. Security tests:
   - Ensure the plugin handles permissions correctly for ICMP operations
   - Verify no sensitive information is exposed in logs or responses

All tests should be automated where possible and included in CI/CD pipeline.
