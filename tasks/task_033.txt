# Task ID: 33
# Title: Implement MQTT-Triggered Gobuster Plugin for HTTP Service Enumeration
# Status: done
# Dependencies: 32
# Priority: high
# Description: Develop a plugin that uses Gobuster to automatically enumerate directories and files on HTTP services when triggered by MQTT messages, utilizing SecLists wordlists and adding enrichments for discovered items.
# Details:
Create a plugin that integrates with our existing architecture to perform automated directory and file enumeration on HTTP services. The plugin should:

1. Subscribe to relevant MQTT topics to receive triggers for scanning (e.g., when new HTTP services are discovered)
2. Upon receiving a trigger, launch Gobuster with appropriate parameters to scan the target HTTP service
3. Utilize SecLists wordlists for comprehensive enumeration (include directory-list-2.3-medium.txt for directories and web-extensions.txt for file types)
4. Implement intelligent wordlist selection based on the target (e.g., different wordlists for different web technologies if detected)
5. Process Gobuster results to identify interesting files and directories (status codes 200, 301, 302, 403 should be considered interesting)
6. For each discovered item, create enrichments including:
   - File/directory path
   - Status code
   - Size (if available)
   - Content type
   - Last modified date (if available)
   - A brief assessment of potential security implications
7. Publish results back to MQTT with appropriate topics for other components to consume
8. Implement rate limiting and respect target limitations to avoid overwhelming services
9. Include proper error handling for timeouts, connection issues, and other potential failures
10. Log all activities with appropriate verbosity levels
11. Ensure the plugin can be configured via environment variables or a configuration file

The plugin should be containerized for easy deployment and should follow our existing plugin architecture patterns.

# Test Strategy:
Testing should verify both functionality and reliability of the plugin:

1. Unit Tests:
   - Test MQTT message parsing and validation
   - Test Gobuster command construction with various parameters
   - Test result parsing and enrichment generation
   - Test error handling for various failure scenarios

2. Integration Tests:
   - Set up a test HTTP server with known directories and files
   - Trigger the plugin via MQTT and verify it correctly discovers the known items
   - Verify enrichments are correctly generated and contain accurate information
   - Test with different HTTP server configurations (Apache, Nginx, IIS)

3. Performance Tests:
   - Verify the plugin handles large wordlists efficiently
   - Test memory usage during scanning of large targets
   - Verify rate limiting functionality works as expected

4. Edge Cases:
   - Test behavior with malformed MQTT messages
   - Test with unreachable HTTP services
   - Test with HTTP services that return unusual status codes
   - Test with extremely slow HTTP services

5. End-to-End Tests:
   - Verify the plugin integrates correctly with other components in the system
   - Confirm MQTT messages are properly published and can be consumed by other components

All tests should be automated and included in the CI/CD pipeline. Documentation should include examples of expected MQTT messages and plugin outputs.
