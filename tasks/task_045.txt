# Title: Implement Nuclei Test Handlers for Tester Plugin
# Status: done
# Dependencies: 35, 37
# Priority: low
# Description: Develop and register test handlers for the Nuclei plugin that verify Docker image readiness, basic scan functionality, results parsing, and configuration loading.
# Details:
Create test handlers for the Nuclei plugin following the established patterns from HttpX and Gowitness Tester plugins. The implementation should include:

1. Docker Image Readiness Handler:
   - Verify the Nuclei Docker image exists and is properly configured
   - Check image version matches expected version
   - Validate container startup and health check

2. Basic Scan Functionality Handler:
   - Implement test that runs a basic Nuclei scan against sample targets
   - Use controlled test templates that produce predictable results
   - Verify scan execution completes without errors

3. Results Parsing Handler:
   - Test the parsing of Nuclei scan results into the expected format
   - Validate all required fields are correctly extracted
   - Check handling of different result types (info, low, medium, high, critical)

4. Configuration Loading Handler:
   - Verify that Nuclei configurations are properly loaded
   - Test with various configuration options (rate limiting, templates, etc.)
   - Validate configuration overrides work as expected

Each handler should follow the existing Tester plugin architecture, implementing the required interfaces and registering with the test registry. Use mocks where appropriate to isolate testing components.

# Test Strategy:
Testing should verify both the handlers themselves and the functionality they're designed to test:

1. Unit Tests:
   - Test each handler in isolation with mocked dependencies
   - Verify handler registration with the test registry
   - Check error handling for each test case

2. Integration Tests:
   - Run the handlers against a real Nuclei container
   - Use a controlled environment with known test targets
   - Verify results match expected outcomes

3. Specific Test Cases:
   - Test image readiness with both valid and invalid image versions
   - Test scan functionality with templates that produce known findings
   - Test results parsing with various output formats (JSON, etc.)
   - Test configuration loading with valid and invalid configurations

4. Validation Criteria:
   - All handlers should register successfully
   - Tests should pass when conditions are met
   - Tests should fail with clear error messages when conditions aren't met
   - Logging should provide clear visibility into test execution

Use the existing test framework to execute these tests both in CI/CD and locally for development.
